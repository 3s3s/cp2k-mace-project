# Руководство по развертыванию и запуску Master-Worker архитектуры (DFT / CP2K)

Данный документ содержит пошаговые инструкции по запуску сервера-Мастера (`main.py`) и воркеров (`worker.py`) в Docker-контейнерах для различных сценариев окружения.

---

## 🛠 Предварительные требования

1. **Файл `main.py` (Master):**
   Убедитесь, что в вызове `uvicorn.run` указан хост `0.0.0.0` (а не `127.0.0.1`), чтобы сервер мог принимать соединения из внешних Docker-сетей или по интернету:
   ```python
   def run_fastapi_server(port: int):
       uvicorn.run(app, host="0.0.0.0", port=port, log_level="warning")
   ```

2. **Зависимости контейнера:**
   Убедитесь, что в Docker-образ установлен пакет `requests` (`pip3 install requests`).

---

## 💻 Сценарий 1: Все компоненты на одной машине (Локально в Docker)

Этот сценарий используется для отладки, когда и Master, и Worker работают на вашем локальном компьютере (или в WSL2), но запущены в **разных** Docker-контейнерах.

### 1.1 Запуск Мастера (Master)

Запустите контейнер с Мастером и выполните `main.py`:

```bash
# 1. Запускаем контейнер для Мастера
./run.sh --cpu --name master --port 8443 --port2 8000

# 2. Внутри контейнера запускаем main.py
python3 ./src/main.py --port 8000
```
> **Что происходит:** Сервер поднимается на порту `8000` внутри контейнера, который пробрасывается на порт `8000` вашего хоста.

### 1.2 Запуск Воркера (Worker)

В **другом терминале** запустите воркер. Скрипт `run.sh` автоматически свяжет воркер с сервером через `host.docker.internal`:

* **Вариант А (Автоматический запуск воркера при старте контейнера):**
  ```bash
  ./run.sh --cpu --name worker1 --port 8444 --port2 8001 --worker
  ```

* **Вариант Б (Ручной запуск из bash-оболочки контейнера):**
  ```bash
  # Запуск контейнера
  ./run.sh --cpu --name worker1 --port 8444 --port2 8001
  
  # Внутри контейнера (переменные MASTER_HOST и MASTER_PORT подтягиваются автоматически)
  python3 ./src/worker.py
  ```

## 🌐 Сценарий 2: Распределенный запуск (Master на удаленном сервере с реальным IP)

Этот сценарий используется для продакшн-расчетов, когда `main.py` запущен на удаленном мощном сервере (например, IP `203.0.113.10`), а воркеры запускаются на локальных машинах или в кластере.

### 2.1 Настройка и запуск на Удаленном Сервере (Master)

1. Убедитесь, что порт `8000` открыт во входных правилах брандмауэра (UFW / Cloud Security Group):
   ```bash
   sudo ufw allow 8000/tcp
   ```
2. Запустите Мастер на удаленном сервере:
   ```bash
   ./run.sh --cpu --name master --port 8443 --port2 8000
   ```
   Внутри контейнера:
   ```bash
   python3 ./src/main.py --port 8000
   ```

---

### 2.2 Варианты подключения Воркера к Удаленному Серверу

#### Способ 1: Прямое подключение по публичному IP (Самый простой)

Используйте флаг `--master-host` для указания реального IP-адреса сервера:

```bash
./run.sh --cpu --name worker1 --port 8444 --port2 8001 --master-host 203.0.113.10 --worker
```

Или, если контейнер воркера уже запущен, вызовите скрипт напрямую с параметром `--server`:
```bash
python3 ./src/worker.py --server 203.0.113.10 --port 8000
```

---

#### Способ 2: Безопасное подключение через SSH-туннель (Рекомендуется)

Если порт `8000` на удаленном сервере закрыт из соображений безопасности (Firewall), вы можете пробросить его через encrypted SSH-туннель.

1. **На машине с Воркером** откройте SSH-туннель в отдельном терминале:
   ```bash
   ssh -N -L 8000:127.0.0.1:8000 user@203.0.113.10
   ```
   *(Данная команда перенаправляет ваш локальный порт 8000 напрямую на порт 8000 удаленного сервера).*

2. **Запустите воркер** как при локальной работе:
   ```bash
   ./run.sh --cpu --name worker1 --port 8444 --port2 8001 --worker
   ```
   *(Воркер будет стучаться в `host.docker.internal:8000`, пробрасываться на ваш локальный хост и через SSH-туннель безопасно уходить на удаленный Master).*

## 🚀 Запуск нескольких воркеров параллельно

Чтобы ускорить обработку очереди задач, вы можете запустить несколько воркеров на одной или разных машинах:

**На одной машине (смена имен и внешних портов):**
```bash
# Воркер 1
./run.sh --cpu --name worker1 --port 8444 --port2 8001 --master-host 203.0.113.10 --worker

# Воркер 2
./run.sh --cpu --name worker2 --port 8445 --port2 8002 --master-host 203.0.113.10 --worker

# Воркер 3
./run.sh --cpu --name worker3 --port 8446 --port2 8003 --master-host 203.0.113.10 --worker
```

Каждый воркер пройдет авто-регистрацию (`worker_1`, `worker_2`, `worker_3`), получит свою уникальную структуру и начнет параллельные расчеты CP2K.

## 🔍 Проверка логов и диагностика

* **Логи Мастера:**
  Файл находится в `results/main.log`. Вы также можете смотреть вывод Uvicorn прямо в терминале Мастера.

* **Логи Воркера:**
  Каждый воркер пишет персональный лог-файл: `results/worker_logs/worker_N.log`.

* **Если Воркер потерял связь:**
  Воркер защищен механизмом `register_with_retry`. При падении или перезапуске сети он продолжит предпринимать попытки переподключения каждые 5 секунд без аварийного завершения процесса.
